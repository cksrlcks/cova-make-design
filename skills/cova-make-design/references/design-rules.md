# 디자인 규칙 (사람이 만든 시안처럼)

## 0. 생성 프로세스 — 2-패스 (건너뛰기 금지)

**유형 분기 먼저:** 메인·서브 스탠다드는 이 파일 + [design-trends.md](design-trends.md)(방향 D), 쇼케이스는 +
[showcase-web.md](showcase-web.md)(아키타입 S), 앱은 + [app-design.md](app-design.md)(아키타입 A) — 아래 '방향'의 후보 3개는
해당 카탈로그에서 세운다.
관리자·도구형 제품은 이 파일의 §2~§4 공통 규칙 + [saas-admin.md](saas-admin.md)를 따른다.

**1차 패스 — 디자인 플랜 선언.** 코드를 쓰기 전에 다음을 확정하고, **완성 HTML 최상단에
design-plan 주석으로 기록**한다(`<!doctype html>` 바로 다음 줄)(주석이므로 화면에는 노출되지 않는다 — 자체 테스트가 이 주석과
실제 CSS의 일치를 대조한다):

```html
<!-- design-plan: 앵커: A 을지로 인쇄소 견적서 · B 약국 조제봉투 | 후보 ①…(기각 사유) ②… ③… | 커밋: D1 에디토리얼 매거진
     | 모드: 스탠다드|쇼케이스(S?) · 연출: 시네마틱(M3·M6·M9) · 포컬: …(쇼케이스만) · 앱이면 아키타입: A? · 플랫폼: 모바일 앱 | 색 전략: Committed(브랜드색 면적 40%) · 장면: 점심시간 사무실 모니터 → 라이트
     | 팔레트: 지면 #eef1f4 / 잉크 #14202b / 코발트 #2748d8 / 살구 #f2a37e | 타이포: Paperlogy 600 × SUIT(본문 선택 이유)
     | 히어로: HC3(기각: HC0 스플릿 — 관행, HC1 — 직전 이력과 중복) | 시그니처: … | 볼륨: 균형(무브 2·6·19) | 비튼 축(D2·D4·금지 팔레트 사용 시): …
     | 섹션맵: hero L1 / 진료 L8 / 고민 L20 / 의료진 L5 / 오시는길 L12 / 푸터 F1
     | 라이브: 채택[…] 회피[보라 그라데이션·마키] (미가용 시 "미조회(문서 기준)")
     | 이력: 최근 [D10·D2·D12] 회피 | 크리틱: 철4 위4 실3 고4 절4 다5 (1패스 수정: …) -->
```

- **앵커(후보의 원료 — A·B로 표기해 후보 번호 ①②③과 섞지 않는다)**: 후보 ②③을 D 번호로 먼저 세우지 않는다. 방문자가 외우고 있는 **구체적인 사물·장소·
  의식**(예: 동네 목욕탕 번호표, 약국 조제봉투, 을지로 인쇄소 견적서, 학원 시간표 게시판)을 브리프의 고유 재료에서
  먼저 뽑고, D·S 카탈로그는 그 앵커를 **렌더링하는 문법**으로만 쓴다. ②와 ③은 재료 계열이 달라야 한다.
  형용사("세련된·깔끔한")는 영역만 가리키고, 구체적 참조 하나는 한 점을 가리킨다.
- **방향**: 앵커 → design-trends.md 카탈로그에서 후보 3개 → 관행 기각 → 1개 커밋 (어드민이면 무드 A/B/C).
- **색 전략**(볼륨과 별개 축): Restrained(무채 + 액센트 한 점) / Committed(브랜드색 면적 30~60%) /
  Full(섹션마다 색 필드) / Drenched(한 색에 몰입) 중 하나. 라이트·다크는 "누가, 어디서, 어떤 빛 아래서
  보는가" 한 문장으로 정한다(습관적 다크·습관적 크림 금지).
- **팔레트**: 이름 붙인 hex 4~6개. **아래 '금지 팔레트 패밀리'를 기본값으로 쓰지 않는다** — 브리프가 명시적으로
  요구할 때만(그때도 비튼 축 2개를 적는다):
  - 배경 웜크림 `#f4f1ea #f5f1ea #f7f5f0 #f7f5f1 #faf7f1 #faf7f2 #f0eee9` 계열
  - 액센트 브라스·클레이·테라코타·옥스블러드 `#9a7b4f #b08947 #9c6e2a #a4502f #5c1a1a` 계열
  - 텍스트 웜블랙 `#191817 #1a1714 #1d1c1a` + 위 배경의 조합
  - 근검정 `#0a0a0a~#0f0f0f` + 애시드그린·버밀리언 단일 액센트
- **이력(런 간 다양성 — 관리자 제외, 같은 계열끼리 비교: D끼리·S끼리·A끼리)**: `~/.cova/history.json`(없으면 생성)의 최근 기록과 비교해, **최근 3건과 커밋 방향이 달라야
  하고** 지면 명도대(라이트/미드/다크)·디스플레이 스타일(세리프/그로테스크/컨덴스드/라운드/손글씨)·액센트 hue 3축 중
  **2축 이상이 같으면 다시 고른다.** 저장 후 한 줄 추가:
  `{"date","industry","mode","commit","anchor","signature","surface"(light|mid|dark),"display"(serif|grotesk|condensed|round|script|mono),"accentHue"(red|orange|yellow|green|teal|blue|violet|magenta|neutral),"hero","footer"}` (앱은 hero·footer 대신 "platform", 최근 20건 유지).
- **타이포**: 헤드라인 폰트 × 본문 폰트 × (선택) 모노 — 역할과 웨이트까지.
- **레이아웃 콘셉트**: 한 문장 (예: "좌측 고정 목차 + 우측 스크롤 아카이브, 섹션마다 폭이 다른 편집 구조").
- **시그니처 요소 1개**: 이 페이지가 기억될 단 하나.
- **섹션 구성**: 브리프에서 도출한 순서 (고정 스켈레톤 금지 — 아래 §2).
- **섹션맵**: design-trends.md "업종별 레이아웃 뼈대"에서 출발해, 각 섹션의 레이아웃을 **실측 레시피 번호**(L1~L20,
  푸터 F1~F5)로 코드 전에 선언한다. 레시피에 없는 구성은 이름을 붙여 적는다. **좌우만 반전한 것은 같은 패밀리.**
  §2의 다양성·상한을 이 선언으로 강제한다. **쇼케이스**는 showcase-web.md의 히어로 H1~H9·섹션 레시피 이름과 푸터 유형을,
  **앱**은 섹션맵 대신 `화면: 홈 / 상세 / 결제 / 완료` 흐름을 적는다.
- **라이브 신호(3.5단계)**: WebSearch 채택/회피 신호를 주석 `라이브:`에 기록(웹 미가용 시 "미조회").

**2차 패스 — 점수형 셀프 크리틱.** 플랜을 6축 1~5점으로 채점하고 주석 `크리틱:`에 남긴다.
**3점 미만 축이 있으면 그 부분을 고쳐 다시 채점**(최대 2회):
- **철학** — 앵커·방향이 브리프의 고유 재료에서 나왔는가 / **위계** — 첫 화면에서 읽는 순서가 하나로 정해지는가
- **실행** — 정렬·간격·타이포 스케일이 규칙대로인가 / **고유성** — 상호만 바꿔 다른 업체에 내도 성립하면 1~2점
- **절제** — 과감함이 시그니처 한 곳에 모였는가 / **다양성** — 이력의 최근 3건·AI 디폴트 룩과 다른가

**콘셉트 부결 테스트(1표 부결):** ① 글자와 로고를 전부 가려도 업종·분위기가 보이는가 ② 상호만 바꿔도 그대로
성립하는가 — ②가 "성립한다"면 고유성은 최대 2점이고 재플랜한다. ③ 한 화면만 보고 떠난 사람이 한 시간 뒤 이 페이지를
**사물로** 묘사할 수 있는가("파란 조제봉투 같은 병원") — 무드로만 묘사되면("깔끔했다") 커밋 실패.
특히 AI 디폴트 룩 3종 + SaaS 카드 키트(동일 radius + `rgba(0,0,0,.1)` 그림자 + 그라데이션 워시)와 겹치는지 검사.
통과한 플랜대로만 구현하고, 모든 색·타이포 결정은 플랜에서 도출한다.

## 1. 레이아웃·정렬

- 콘텐츠 폭은 섹션 의도에 따라 **가변** — 좁은 읽기 컬럼 / 기본(≈1180~1240px) / 넓게 / 풀블리드 중
  고른다. `.inner`(좌우 패딩 데스크톱 32 / 태블릿 24 / 모바일 20px)는 필요할 때 쓰는 가변 컨테이너이고,
  없는 섹션도 정상이다.
- 판단 기준은 '고정 레일'이 아니라 **의도된 폭 + 좌측 정렬 기준선**. 콘텐츠가 브라우저 끝에 붙는 것이
  의도라면 OK, 의도 없이 붙거나 넘치면 실패. 풀폭 배경은 `section`이, 폭 제한은 컨테이너가 담당.
- **페이지당 1~2개 섹션만 연출한다** — 수상작의 실제 연출 레시피(L3 스티키 장면·L4 인셋 프레임 확대·L5 진행바
  캐러셀·L6 센터모드·L7 제목 리스트×비주얼·L15 영문 키워드·L16 스택 카드) 중에서 고른다. 정적 섹션을 화면 밖으로
  흘리는 편측 흘림은 쓰지 않는다(화면 밖 잘림은 캐러셀 끝에서만). 연출 섹션에서도 좌측 기준선은 유지.
- 한 페이지의 주요 텍스트 시작점은 같은 좌측 기준선. 정보형 섹션은 좌측 정렬 기본, 가운데 정렬은
  필요한 곳만(D12 소프트 프로덕트는 중앙 정렬이 관례).
- 섹션 간격은 정보 흐름에 따라 72 / 96 / 120px(D2 콰이어트 럭셔리는 140px+)로 변주 — 전부 동일 간격 금지.
  본문 텍스트 폭 `max-width: 520~680px`.
- **메인 히어로는 첫 화면을 지배하는 것이 기본** — `min-height: 92~100vh`(업종 뼈대가 다르면 그것을 따른다: 커머스 멀티카드 60~70vh, 호텔 85vh / 에디토리얼·럭셔리 방향은
  76~88vh 허용). **한글 헤드라인은 2~3줄 선언문 32~56px**(수상작 실측) — 첫 화면은 글자 크기가 아니라
  이미지·영상·색 필드로 지배한다. **히어로 구도는 design-trends.md '히어로 구도 HC0~HC9'에서 먼저 번호로 고른다 —
  좌 텍스트·우 이미지 스플릿(HC0)은 항상 기각 후보 ①**(쓰려면 plan에 이유). 이미지든 타이포든 방향의 히어로 문법을 따르고, "중앙 정렬 + pill 뱃지 + 큰 제목 +
  버튼 2개"의 템플릿 히어로는 금지. 서브·관리자·제품 유형에는 풀스크린을 강제하지 않는다.
- **관리자·도구형 제품**은 마케팅 문법 대신 [saas-admin.md](saas-admin.md)의 앱 셸(사이드바+상단바)과
  화면 골격을 따른다. 후기·CTA 같은 마케팅 섹션을 억지로 넣지 않는다.

## 2. 섹션 다양성 (AI스러움 방지)

- **고정 스켈레톤 금지**: "히어로 → 아이콘 3열 카드 → 로고월 → 통계 배너 → pricing → FAQ → CTA"는
  AI 서명이다. 섹션 구성은 업종·목적(인터뷰 답)에서 도출한다.
- 8개 섹션이면 레이아웃 4종 이상(L 레시피 번호 기준). **zigzag(텍스트-이미지 교대)는 최대 2행**(수상작 3행+ 0/51) —
  룩북·지점처럼 항목이 본래 쌍일 때만. **좌텍스트·우이미지는 페이지당 최대 2회.**
  업종 필수 블록(뼈대)을 먼저 채우고, 빈 섹션을 장식 부품(아이콘 3열·스탯 행·후기 카드·FAQ)으로 메우지 않는다.
  §0에서 선언한 섹션맵이 이 규칙을 만족해야 하며, 못 하면 섹션맵을 다시 짠다(중앙정렬 관례인 D12는 예외).
- 3열 카드 반복 금지. 섹션마다 밀도·여백·이미지 비율을 다르게 — 모든 섹션이 같은 max-width·radius·
  shadow·간격이면 실패.
- eyebrow(위 라벨)는 3섹션당 1개 이하, **pill 배지 금지**(작은 텍스트 라벨만). 의미 없는 01/02/03 번호 장식 금지(실제 절차·순서일 때만).
  섹션 헤더는 "좌 제목 + 우 전체보기 →"가 수상작 기본형.
  eyebrow 셈법: 히어로 라벨 포함, L3 장면 라벨처럼 한 컴포넌트가 반복하는 라벨은 1개로, L8처럼 라벨이 제목을 대신하면(아래 h2 없음) 세지 않는다.
- 섹션 타입(참고): hero, intro, about, service, product, portfolio, gallery, process, pricing,
  review, faq, contact, cta, footer — 이 중 브리프에 필요한 것만.
- 차별화 장치는 방향의 무브 세트에서. 볼륨(절제/균형/과감)은 design-trends.md 사용법을 따른다.

## 3. 타이포

- **국문은 본문·헤드라인 모두 고딕 계열만.** 명조·바탕·붓·궁서 느낌·손글씨 국문 폰트는 사용자가 명시 요청할 때만 —
  세리프·손맛은 라틴 폰트로 영문 단어에만(design-trends.md 타이포 팔레트 상단 원칙).
- **본문 폰트도 방향에서 고른다 — Pretendard는 기본값이 아니라 선택지 중 하나다.**
  design-trends.md 타이포 팔레트의 '본문' 행(Pretendard / SUIT / Wanted Sans / Spoqa Han Sans Neo /
  나눔스퀘어 네오 / Noto Sans KR / IBM Plex Sans KR / Gowun Dodum 등 — **전부 고딕**)에서 방향의
  성격에 맞는 것을 고른다. 매번 Pretendard로 수렴하면 그것도 AI 기본값이다 — 특별한 이유(정보
  밀도·중립성)가 없으면 다른 본문 폰트를 먼저 검토하고, 고른 이유를 design-plan 타이포 필드에 남긴다.
  예) 로드 + `body { font-family: "SUIT Variable", "Pretendard", -apple-system, "Apple SD Gothic Neo", "Malgun Gothic", sans-serif; }`
- **헤드라인은 방향에서 도출한 디스플레이 폰트를 쓴다**(design-trends.md 타이포 팔레트의 검증 CDN).
  본문과 헤드라인이 같은 무개성 고딕이면 개성 실패("Pretendard 단독"은 어드민 전용).
- 라틴 디스플레이 폰트(쇼케이스 모드 등)는 **영문 워드마크·영문 헤드라인에만** 쓴다 — 국문이 섞이는
  헤드라인은 한글 지원 폰트로(폴백으로 깨진다).
- **국문 웨이트는 SemiBold(600)가 상한이다.** Bold(700+)는 정말 필요한 1곳에만 쓰고 plan에 이유를 적는다.
  위계는 굵기가 아니라 **크기·색·자간·여백**으로, 대비는 얇음(200~300)과 500~600 사이에서 만든다. 라틴(영문) 워드마크·숫자는
  더 무거워도 된다. 본문 400 / `line-height: 1.6~1.75`.
- 국문 헤드라인은 `letter-spacing: -0.01~-0.03em` + `word-break: keep-all` + 줄바꿈 위치 직접 설계.
- 크기 단계는 3~4개로 압축, 단계 간 배율 1.3배 이상.

## 4. 폰트 세로 정렬 (중요 — 가장 흔한 결함)

- 뱃지·버튼·칩처럼 텍스트를 감싼 작은 박스는 **flex로 중앙 정렬**한다. padding만으로 맞추지 않는다:
  ```css
  .button, .badge, .chip {
    display: inline-flex;
    align-items: center;      /* 세로 정중앙 */
    justify-content: center;  /* 가로 정중앙 */
    line-height: 1;           /* 고정 높이 요소는 1로 두고 padding으로 높이 확보 */
  }
  ```
- 아이콘+텍스트는 `gap`으로 간격, 두 자식 모두 flex 중앙. 고정 `height` 버튼/뱃지는 `line-height`가
  글자를 밀지 않는지 자체 테스트에서 확인.

## 5. 색·디테일

- 팔레트는 1차 패스에서 선언한 4~6색만 쓴다. 액센트는 1색(D6 도파민 팝만 2~3색 충돌 허용).
- 구분은 그림자보다 여백·배경 톤·얇은 선·타이포 위계로 먼저. `border-radius`는 하나의 시스템으로
  통일(각짐 0~4 / 표준 6~10 / 둥긂 12~20 중 방향에 맞는 것 하나 — 페이지 안에서 섞지 않는다.
  pill은 인터랙티브 요소만).
- CSS 변수를 먼저 정의: `--page-max`, `--side-padding`, `--section-space`,
  `--color-primary/text/muted/line/bg/bg-soft` 등. 브랜드색 파생에 oklch를 쓸 때 폴백은
  **사용처에서**(`background: #hex; background: var(--brand-deep);`) — 커스텀 프로퍼티 선언
  자체에는 hex→oklch 덮어쓰기 폴백이 동작하지 않는다(design-trends.md 색 시스템 팁 참조).
- 공통 레이아웃 클래스: `.page`, `.section`, `.section--tone`, `.inner`(가변 폭·옵션), `.grid`,
  `.eyebrow`, `.section-title`, `.section-desc`, `.button`. 단, 모든 섹션을 같은 컴포넌트처럼 보이게
  하지 않는다.
- CSS 특이성 주의: `.section` 같은 타입 셀렉터와 요소 셀렉터가 서로 상쇄되지 않게 — 섹션 간
  padding/margin이 예고 없이 겹치는 흔한 원인.
- 모션은 design-trends.md D섹션의 안전 열화 규칙을 따른다: 최종 상태가 기본값,
  연출은 `@supports` + `prefers-reduced-motion` 게이트 안에만.

## 6. 이미지

- **무료 이미지 사이트의 실제 URL**로 넣는다(플레이스홀더 회색 박스 금지):
  - Unsplash: `https://images.unsplash.com/photo-<id>?w=1600&q=80` (알고 있는 실제 photo id 사용.
    `source.unsplash.com`은 서비스 종료 — 쓰지 않는다.)
  - Pexels: `https://images.pexels.com/photos/<id>/...jpeg?auto=compress&w=1600`
- **HTML에 넣기 전에 curl로 검증한다**: 후보 URL들을 `curl -s -o /dev/null -w "%{http_code}" <url>`로
  일괄 확인해 200이 아닌 것은 버린다. 유효한 이미지를 못 구한 영역은 회색 박스가 아니라 **방향의
  팔레트로 만든 듀오톤 컬러 블록 + 타이포 그래픽**으로 폴백한다(사진 주도 방향이면 유효 이미지를
  구할 때까지 키워드를 바꿔 재시도).
- 자체 테스트에서도 모든 이미지의 실제 로드(naturalWidth > 0)를 재확인하고, 깨진 것은 교체한다.
- **200 응답은 내용을 보장하지 않는다.** photo id는 기억에 의존하므로, 후보 사진을 작은 컨택트시트(HTML 한 장에 썸네일 격자)로
  렌더링해 **눈으로 보고** 고른다(엉뚱한 수술실·다른 도시 랜드마크 방지).
- **사진 선택 우선순위**: ① 공간·사물·재료·손(얼굴 없음) ② 한국·아시아 맥락이 읽히는 인물 ③ 뒷모습·실루엣. 한국 동네 업종에
  서구 스톡 인물 정면 컷은 쓰지 않는다. 브리프의 지역(성수·을지로 등)과 **다른 장소가 식별되는 사진**(타 도시 랜드마크)도 금지.
- 좋은 사진을 못 구하면 사진 주도 구도(HC1·HC2·HC3·HC5)를 포기하고 사진이 필요 없는 구도(HC6·HC7·HC8)로 간다 —
  약한 스톡 사진을 크게 쓰는 것이 가장 나쁘다.
- hero / 소개 / 사례 영역은 비율을 서로 다르게. `figure`+`figcaption`, 설명형 `alt`.
- 이미지 톤은 인터뷰의 방향(실사/제품컷/일러스트)을 따르되, 방향의 질감 처리(duotone·그레인·
  마스크 셰이프)를 입혀 "스톡 사진 그대로" 느낌을 지운다.
- 코드로 어설프게 그린 손그림풍 SVG 일러스트는 역효과 — 일러스트가 필요하면 실제 이미지 에셋을
  쓰거나 도형·타이포 그래픽으로 대체한다.

## 7. 카피·태그

- 한국어. **제품·서비스가 실제로 하는 일을 구체적 동사+명사로** 쓴다. 사용자의 상황을 서술한다
  ("대기 없이 오늘 저녁 예약" > "스마트한 예약 솔루션").
- 금지 어휘·패턴: "혁신적인/최고의/새로운 기준/완벽한", 번역투("~을 통해", "당신의 비즈니스를"),
  em-dash(—) 남발, 모든 문장이 같은 종결어미로 끝나는 균일 리듬.
- **핵심 데이터가 비었을 때**(시그니처·히어로가 영업시간·가격·주소 같은 실데이터에 기대는데 브리프에 없음): 인터뷰에서
  1회 추가로 묻는다. 무인 실행이거나 답이 없으면 업종 관행 값을 쓰되 `data-example` 속성을 달고 결과 안내에 "예시값 — 실데이터 확인
  필요" 목록으로 알린다. 연락처·대표자·사업자번호는 `02-000-0000`·`○○○`처럼 형태만.
- 주어지지 않은 브랜드명·수치·후기·인증마크를 사실처럼 지어내지 않는다. 가짜 정밀 숫자
  (만족도 98%, 4.9/5.0) 금지 — 데이터가 주어졌을 때만 숫자를 쓴다.
- 버튼·CTA는 눌렀을 때 일어나는 일을 그대로 ("상담 예약하기", "메뉴 보기" — "자세히 보기" 남발 금지).
  같은 액션은 페이지 전체에서 같은 이름(내비·히어로·푸터 모두 — **같은 의도의 CTA를 다른 라벨로 두지 않는다**).
- CTA 규율: 히어로는 primary 1 + secondary 최대 1. 버튼 라벨은 **줄바꿈 금지**(`white-space: nowrap`, 국문 ≈8자 이하).
  모든 버튼 끝에 기계적으로 `→` 붙이지 않는다(외부 이동·다음 단계일 때만).
- **카피 셀프 감사**: 완성 후 화면의 모든 문자열을 다시 읽는다. 걸러낼 것 — 시적·장인척하는 라벨("현장의 기록",
  "조용히 신뢰받는"), 헤딩 아래 붙는 메타 문장, 경구체 리듬("~이 아닙니다. ~입니다." 류 대구 2회 이상),
  `A · B · C` 가운뎃점 메타 문자열, `단어 — 조각` 라벨, 의미 없는 "STEP 1"·버전 스탬프·장식용 사진 크레딧.
  **AI처럼 귀여운 카피는 지루한 카피보다 나쁘다** — 애매하면 담백하게.
- 선택 태그는 방향 결정에만 쓰고 화면에 노출하지 않는다. 충돌하는 태그는 업종·목적에 더 맞는 쪽 우선.
  태그가 많으면 핵심 태그 3~5개를 중심축으로.

## 8. 업종별 정보 구조 (우선순위)

- 병원·교육·금융·B2B — 신뢰, 절차, 전문성, 검증 요소
- 숙박·여행·레저·식음료 — 이미지 몰입감, 가격/예약/위치, 경험 중심 카피
- 쇼핑·제품·브랜드 — 차별점, 사용 장면, 구성 옵션, 구매 판단 요소
- 공공·기관·협회 — 안정감, 명확한 안내, 접근성, 정보 전달력
- 스튜디오·IT·플랫폼 — 문제 해결 흐름, 기능 설명, 사용 사례, 운영 효율
- 로컬 매장·생활 서비스 — 위치, 운영 시간, 이용 절차, 문의 흐름 (+ 카카오톡 채널·전화 CTA 관례)
- 푸터에는 법정 정보 자리(상호·대표자·사업자등록번호·주소·개인정보처리방침)를 확보한다 —
  실데이터가 없으면 형태만 잡고 지어내지 않는다.

## 9. 출력 전 자체 점검

- 첫 화면만 보고 업종과 목적이 이해되는가? **그리고 이 시안만의 개성(시그니처)이 보이는가?**
- 선언한 방향·팔레트·타이포가 실제로 구현됐는가(플랜과 결과물의 일치)?
- AI 클리셰 스캔: 보라 그라데이션 / 아이콘 3열 카드 / 카드 좌측 컬러바 / 이모지 아이콘 /
  pill eyebrow + 중앙 히어로 / 고정 스켈레톤 / **무브 14 허용 목록(D5·D6·D9·뷰티/F&B 슬로건 띠·쇼케이스 S3·S4·S9·S10·테이프 띠) 밖 마키·마키 2개+** · 빅 풋터 반사 · 한글 초대형 헤드라인(D11·쇼케이스 제외) — 하나라도 있으면 수정.
- 각 섹션의 폭·정렬이 의도적이고, 좌측 기준선이 흔들리지 않는가?
- 섹션이 같은 카드 패턴·같은 간격으로 반복되지 않는가(레이아웃 패밀리 4종+)?
- 카피가 실제 클라이언트 제안서 수준인가? 금지 어휘가 없는가?
- CTA는 primary/secondary 위계가 분명하고 필요한 지점에만 있는가?
- 모바일(1열)에서 구조가 무너지지 않는가? (단, 데스크톱 완성도 우선)
- 모션의 기본 상태가 완성형인가(opacity:0 기본값 사고 없음)? reduced-motion을 존중하는가?

## 10. 품질 바닥 (모델이 가장 자주 빼먹는 "만들어진 페이지" 신호)

- `:root`에 `color-scheme`(light/dark), `<meta name="theme-color">`. 색·폰트는 `:root` 토큰으로 선언하고 규칙에서는 `var()`로 쓴다(레시피 코드의 hex도 토큰으로 옮겨 쓴다). `style=""` 속성에 색을 박지 않는다.
- `::selection`(브랜드 틴트), `caret-color`, 링크 `text-underline-offset: .2em`.
- 포커스: 모든 인터랙티브 요소에 **즉시 나타나는 `:focus-visible`**(배경 대비 3:1 이상, 예: `outline: 2px solid var(--accent); outline-offset: 3px`).
  sticky 헤더가 포커스 대상을 가리지 않게 `scroll-margin-top`.
- 숫자: 가격·통계·표는 `font-variant-numeric: tabular-nums`, 숫자와 단위 사이 `&nbsp;`, 말줄임은 `…` 문자.
- 스킵 링크(`본문 바로가기`) + 헤딩 순서(h1 1개 → h2 → h3). 대비 본문 4.5:1, 큰 글자 3:1.
- `transition: all` 금지(속성을 명시). 5초 넘게 도는 자동 모션(마키·루프)은 `:hover`/`:focus-within`에서
  `animation-play-state: paused` — CSS만으로 일시정지 수단을 준다.
- 안전 스니펫: `html, body { overflow-x: clip }`, 이미지 그리드 트랙은 `minmax(0, 1fr)`, 디스플레이 제목은
  `overflow-wrap: anywhere; min-width: 0`, 중첩 radius는 자식 ≤ 부모.
- 히어로 맞춤(1280×800 기준): 헤드라인·리드·주 CTA가 **스크롤 없이** 보인다. 헤드라인 데스크톱 2줄(국문 최대 3줄),
  리드 2줄(≈60자) 이하, 히어로 텍스트 요소 최대 4개(라벨·제목·리드·CTA 묶음). 신뢰 스트립·가격 티저는 히어로 밖으로.
