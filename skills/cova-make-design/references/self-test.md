# 자체 테스트 (생성 직후, 반드시)

만든 HTML을 실제로 열어 렌더링·정렬·폰트를 점검한다. Playwright MCP가 있으면 그걸로, 없으면
`npx playwright` 또는 로컬 정적 서버로 연 뒤 스크린샷/DOM을 확인한다:

```bash
# 예: 데스크톱 + 모바일 폭에서 스크린샷
npx --yes playwright screenshot --viewport-size=1440,2200 design-<slug>.html shot-desktop.png
npx --yes playwright screenshot --viewport-size=390,1600  design-<slug>.html shot-mobile.png
```

## 0. 기계 검사 (먼저, 눈 검사 전에)

스킬 폴더의 [scripts/cova-check.mjs](../scripts/cova-check.mjs)를 작업 폴더로 복사해 실행한다
— **playwright가 설치된 폴더에서 실행해야 import가 된다.** 없으면 임시 폴더에 `npm i playwright && npx playwright install chromium`
후 그 폴더로 스크립트를 복사하고 HTML은 절대 경로로 넘긴다:

```bash
cp "<스킬 경로>/scripts/cova-check.mjs" . && node cova-check.mjs design-<slug>.html [--mode=web|app|admin]
```

reduced-motion으로 1440·1280·390 폭을 열어 측정한다 — **FAIL은 반드시 고치고, WARN은 의도가 아니면 고친다.**
검사 항목: 가로 스크롤 / reduced-motion에서 opacity:0 텍스트 / 깨진 이미지 / 폰트 폴백 / 마키 2개+ / 이모지 /
design-plan 필드(섹션맵·라이브·크리틱·이력) / 1280×800 히어로 헤드라인·CTA 첫 화면 안 / h1 줄 수 / h2:본문 배율 ≥1.25 /
본문 줄 길이(국문 ≈46자) / 행간 ≥1.3 / eyebrow 수 ≤ ⌈섹션/3⌉ / CTA 줄바꿈 / 본문 대비 AA / `transition: all` /
그라데이션 텍스트 남용 · 스플릿 히어로(HC0) 감지 · 앱: 폰 프레임 밖 넘침·짧은 라벨 쪼개짐. 캡처는 측정 전에 **뷰포트 단위**로 찍힌다(`*.check-<폭>-<n>.jpg`, 폭별 최대 8장 — 풀페이지 한 장은 축소돼 판독이 안 된다). 아래 눈 검사에 그대로 쓴다.
모드는 `.phone`이 있으면 app으로 자동 판정(히어로·eyebrow·390 가로 스크롤 생략), 관리자는 `--mode=admin`(390 대신 1024).

## 0-1. 새 눈 리뷰 (Agent 도구가 있으면, 최대 2라운드)

같은 컨텍스트의 자기 채점은 낙관 편향이 있다. 기계 검사 통과 후 **대화 이력 없는 서브에이전트**를 하나 띄워
리뷰만 맡긴다. 입력은 ① 브리프 요약(업종·목적·타깃·고유 재료) ② design-plan 주석 ③ 1440·390 스크린샷 경로
④ 기계 검사 WARN 목록뿐이다. 지시: "이 시안을 처음 보는 아트디렉터로서, design-rules.md §0의 6축(철학·위계·실행·고유성·절제·다양성)으로
채점하고 콘셉트 부결 테스트를 돌린 뒤, **고칠 것 목록만** 우선순위로 5개 이내 반환하라. 칭찬 금지."
돌려받은 목록을 **한 번에** 반영하고 기계 검사를 한 번 더 돌린다. **2라운드는 1라운드에서 3점 미만 축이 있었을 때만** 돌린다(없으면 1라운드로 끝). 두 번째 리뷰에서도 3점 미만 축이 나오면
한 번 더 고치고 끝낸다(무한 루프 금지). **라운드 간 지적이 서로 엇갈리면**(1R "줄여라" vs 2R "키워라") plan의 시그니처·포컬을 기준으로 한쪽을 고르고 이유를 `크리틱:`에 한 줄 남긴다. Agent 도구가 없으면 이 단계를 건너뛰고 결과 안내에 "새 눈 리뷰 생략"을 적는다.

## 1. 렌더링·정렬 (문제가 있으면 고치고 다시 확인)

- 레이아웃이 깨지거나 요소가 겹치지 않는가. 콘텐츠가 브라우저 끝에 붙는 것이 의도된 것인가.
- 섹션들의 좌측 정렬 기준선이 어긋나지 않는가.
- **뱃지·버튼·칩의 텍스트가 세로 정중앙에 오는가** (design-rules.md의 flex 규칙 — 가장 흔한 결함).
- 선언한 폰트가 **전부** 실제 적용됐는가 — 본문(방향에서 고른 본문 폰트)과 헤드라인 디스플레이 폰트 각각
  확인(시스템 폰트로 폴백되지 않았는가). `document.fonts.check('700 1em <폰트명>')`로 검사 가능.
- 사용한 외부 이미지가 실제로 로드되는가(`img.naturalWidth > 0`, 깨진 이미지는 교체).
- 모바일 폭(≈390px)에서 1열로 자연스럽게 정리되는가. 오버랩·회전 요소가 모바일에서 풀리는가.
  **예외: 관리자·도구형 제품은 390px 검사 대신 1024px에서 사이드바 축소(아이콘 레일)와 테이블
  overflow 스크롤이 동작하는지 확인**(saas-admin.md 뷰포트 규칙).
- 의도치 않은 가로 스크롤이 없는가(흘림 캐러셀·풀블리드 요소가 있으면 `html, body { overflow-x: clip }` — html 단독은 효과 없음).

## 2. 개성·클리셰 스캔 (사용자 페이지)

- **HTML 최상단에 design-plan 주석이 존재하는가**(design-rules.md §0) — 없으면 1차 패스를
  건너뛴 것이므로 실패.
- **주석에 `섹션맵`·`라이브` 필드가 있는가** — 없으면 섹션 설계/3.5 라이브 스캔을 건너뛴 것(실패).
- **주석의 선언과 실제 CSS가 일치하는가** — 주석의 팔레트 hex·폰트명·무브 번호를 grep으로
  본문 CSS와 대조한다(플랜 따로 결과 따로 금지). D2·D4 커밋이면 "비튼 축" 2개가 실제 구현됐는가.
- **3.7에서 사용자가 고른 레이아웃(`(사용자 선택)`)이 섹션마다 그대로 구현됐는가** — 임의로 바꿨으면 실패.
- **히어로 구도가 plan의 `히어로: HC?`와 일치하는가** — 좌 텍스트·우 이미지로 나왔는데 plan에 HC0 사유가 없으면 실패.
- 스티키 스택(M4·L16)은 정적 캡처에서 카드가 겹쳐 보이는 게 정상이다 — 판독은 모션 모드로 한 화면씩 내리며 확인한다.
- **국문 텍스트가 전부 고딕인가** — 국문에 명조·바탕·손글씨 폰트가 걸렸으면 실패(사용자가 명시 요청한 경우 제외).
- **시그니처 요소가 실제로 존재하는가** — 스크린샷에서 "이 시안만의 한 방"이 보이는가.
- **마키 남용이 없는가** — `@keyframes marquee`/`translateX(-50%)` 애니메이션이 **페이지당 최대 1개**,
  그리고 커밋 방향이 **D5·D6·D9일 때만**(쇼케이스면 S3·S4·S9·S10 또는 테이프 띠) 존재하는가. 그 외 방향에 있거나 2개 이상이면 실패
  (`grep -c "translateX(-50%)"`로 카운트).
- AI 클리셰가 없는가: 보라-인디고 그라데이션 / 아이콘 3열 카드 / 카드 좌측 컬러 보더 /
  이모지 아이콘 / pill eyebrow + 중앙 히어로 템플릿 / 의미 없는 01·02 번호 / "혁신적인" 류 카피 /
  AI 디폴트 룩 3종 공식 그대로.
- 섹션 레이아웃이 **주석의 섹션맵대로** 4종 이상 변주되는가 — 섹션맵 선언과 실제 DOM을 대조한다.
  **좌우만 반전한 같은 패밀리는 1종으로 카운트.** 4종 미만이거나 좌텍우이미지가 3회 이상이면 실패.

## 2-1. 쇼케이스 추가 점검 (showcase-web.md)

- **스크린샷 함정**: 스크롤 연동(`animation-timeline: view()`) 요소는 풀페이지 스크린샷에서 "진입 전" 상태
  (투명·밀려남)로 찍힌다. 정적 점검은 **reduced-motion으로** 찍고(Playwright 스크립트에서
  `page.emulateMedia({ reducedMotion: 'reduce' })`), 연출 점검은 기본 모드로 `mouse.wheel`로 한 화면씩
  내리며 여러 장 찍는다. 프리로더(M9)가 있으면 **2.5초 이상 대기** 후 촬영.
- 주석의 `모드: 쇼케이스(S?)`·`연출:` 필드가 있고, 선언한 모션 번호(M?)가 CSS에 실제로 있는가(3~5개, 서로 다른 장치).
- 극단 스케일이 실제로 구현됐는가 — 히어로 최대 요소 ≥ 8vw(S3 타이틀 스택·S7은 예외), 최소 라벨 ≤ 12px, 대형 타이포 행간 ≤ 0.95(국문 ≤ 1.0).
- SaaS 회귀 없음 — 헤드라인 아래 버튼 2개, 로고 월, 아이콘 3열 카드, 스탯 3개 한 줄, 라운드+그림자 카드(S5 제외)가 0개.
- **Firefox·reduced-motion 폴백**에서 M3 핀 가로 스크롤이 빈 300vh를 남기지 않는가(높이 선언이 `@supports` 안에 있는가).
- 인터스티셜 1~2개가 섹션맵에 있는가. 푸터가 히어로와 같은 장치(초대형 타이포)를 반복하지 않는가.

## 2-2. 앱 추가 점검 (app-design.md)

- 폰 프레임 390×844, 상태바·다이내믹 아일랜드·홈 인디케이터가 있고 풀블리드 위에서 상태바 색이 반전되는가.
- 프레임 3~5장이 **하나의 사용자 흐름**으로 이어지는가, 각 프레임 아래 화면명 캡션이 있는가.
- 마지막 콘텐츠가 탭바·스티키 CTA에 가려지지 않는가(`padding-bottom` 확보). 터치 타깃 ≥ 44px.
- 아이콘이 인라인 SVG인가(이모지 0개). radius가 아키타입 토큰 하나로 통일됐는가.
- 쇼케이스면 6개 레버 중 최소 4개가 스탠다드와 달라졌는가 — 특히 '무대'(풀블리드 색·사진·거대 숫자·워드마크)가 화면마다 1개 있는가.
- 좁은 뷰포트(≈390)에서 캔버스가 프레임을 세로로 스택하는가(가로 스크롤 없음).

## 3. 어드민 추가 점검 (관리자·도구형 제품)

- 본문이 13~14px 밀도인가(마케팅 사이즈 16~18px로 커지지 않았는가). 행 높이 40~48px(밀집 36~40).
- 테이블 숫자가 **우측 정렬 + tabular-nums**인가. 헤더가 sticky인가.
- 상태 표시가 dot/뱃지 + 라벨 텍스트인가(색만으로 전달 금지), 뱃지가 저채도 배경+진한 텍스트 공식인가.
- 목데이터가 현실적인가 — 홍길동 반복·라운드 넘버 금액·균등 상태 분포·전부 같은 날짜가 없는가.
- 마케팅 요소(히어로·후기·CTA 배너·오버사이즈 타이포)가 섞여 들어오지 않았는가.
- 그림자가 억제되어 있는가(헤어라인 보더 위주), radius ≤ 12px, 이모지 아이콘 0개.

## 4. 모션·폴백

- 애니메이션 대상의 **기본 상태가 완성형**인가 — `opacity: 0`이 `@supports`/`@media` 게이트 밖에
  있으면 미지원 브라우저에서 콘텐츠가 사라진다(치명 결함).
- `prefers-reduced-motion`을 존중하는가. transform/opacity 외 속성을 애니메이션하지 않는가.
- scroll-driven·backdrop-filter 등은 미지원 환경에서 자연스럽게 열화되는가.

## 팁

- 스크린샷을 눈으로 확인할 수 없으면 DOM 검사로 대신한다:
  뱃지/버튼 요소의 `getBoundingClientRect()`와 내부 텍스트 노드의 rect를 비교해
  위/아래 여백 차가 2px 이내인지 확인하는 식.
- 이미지 로드는 `page.on('response')` 또는 각 `img`의 `naturalWidth > 0`으로 확인할 수 있다.
- 클리셰 스캔은 grep으로도 일부 가능: `grep -c "linear-gradient(.*#[68].*f" ` (보라 계열),
  이모지 유니코드 범위, `border-left: [34]px` 등.
